# Бектест BizDev-агента

Таск cfb5898d (BizDev-агент · 3/8). Калібровка без живого трафіку: реальне повідомлення клієнта з архіву, справжню відповідь ховаємо, агент пише свою, Марко бачить дві поряд і розмічає. 50 архівних ситуацій і 20 синтетичних під трафік-угоди.

Дані в git не лежать: архів, замасковані ситуації й чернетки живуть лише в базі `bizdev-db` (таблиці `backtest_*`, `deploy/initdb/05-backtest.sql`). Тут — код, добір і вигадані сценарії.

## Прогін `bt2` — BizDev-чати по трафіку (15.10, правка Марка)

`bt1` будувався на чатах менторства: там баєри питають «як зробити», і чернетки виходили відповідями на навчальні питання. Для угод це не підходить, тож `bt2` взято з BizDev-чатів, які Марко зібрав у папку (експорти Telegram King-go90, Moonroll, Sezin і діалоги 2up.io, VIVO 360, 10Panda у .docx):

1. `node select-bizdev.mjs <папка BizDev> sel.json` — розбір (`lib/bizdev-archive.mjs`), пари «повідомлення партнера → відповідь Марка» (до 12 год), добір `curation-bizdev.json` (чат, час, автор, тип), маскування. Справжня відповідь — лише Марка; Павло й Степан — у контексті, але не «партнер» і не відповідь. Ролі учасників (оператор / наш баєр) зберігаються, щоб агент бачив, хто пише.
2. Стильовий профіль v1 — з 207 відповідей Марка в цих чатах (`profile/style-profile.md` → вузол `bizdev-agent-style-profile`). Перевірено, що в профілі немає жодного фрагмента справжніх відповідей 50 ситуацій.
3. Далі як для `bt1`: `build-batches.mjs` (пачок стає більше, коли відповіді ситуацій стоять у контекстах одна одної), чернетки наосліп, `load.mjs … bt2`.

Розмітка `bt1` лишається в базі; портал за замовчуванням показує новіший прогін, старіший — перемикачем.

## Як зібрано прогін `bt1`

1. **Архів.** Ноди сегмента «Чати Телеграм» (лише читання) → `nodes.jsonl`, по рядку `{slug, title, content}`.
2. **Добір** `node select-archive.mjs nodes.jsonl sel.json --curation curation.json`. Кандидат — пачка повідомлень клієнта і наша відповідь першою, не пізніше ніж за 45 хв. `curation.json` — добір очима (чат, час, тип): евристика інколи зводить повідомлення з відповіддю про інше. Усе проходить `lib/mask-archive.mjs`: гаманці, коди, паролі, картки, ключі, email, телефони, IP.
3. **Синтетичні** — `synthetic.json`, 5 типів по 4: старт тріалу, слабкі цифри, нове гео, звіт запізнюється, партнер замовк. Вигадані, з вигаданою карткою угоди.
4. **Пачки** `node build-batches.mjs sel.json synthetic.json <dir>`: паспорт ролі + стильовий профіль + ситуації без справжніх відповідей, по 10 у пачці. Ситуації, у чийому контексті стоїть справжня відповідь іншої, не потрапляють в одну пачку.
5. **Чернетки** пише модель, яка справжніх відповідей не бачила (у прогоні `bt1` — Sonnet 5.5, окремий субагент на пачку). Формат відповіді — у кінці пачки.
6. **Завантаження** `node load.mjs situations.json <drafts-dir> bt1 "<модель>"`: перевіряє, що кожна ситуація має чернетку потрібної форми, і пише в базу. Повторний запуск не чіпає рішення Марка.

## Де що правиться

- `profile/style-profile.md` — початкова копія стильового профілю; **джерело правди — вузол `bizdev-agent-style-profile` у базі знань**, він правиться без деплою.
- Рішення Марка лягають у `backtest_decisions`; приклади для агента збирає `export-examples.mjs` у вузол `bizdev-agent-examples`.
